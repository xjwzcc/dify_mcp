# 吴山苑酒店教学系统：阿里云部署指南

本目录准备了 Docker Compose + Caddy 部署文件，未购买或创建云资源，未上传学生数据库，未开通公网网址。以下命令在购买后的 Ubuntu 云服务器执行，不能在当前 Windows PowerShell 中直接执行。

## 一、购买建议

首选阿里云“轻量应用服务器”。建议上海或杭州地域、x86_64、2 核 4GB、至少 60GB SSD、Ubuntu 24.04 LTS 纯净系统镜像、带公网 IPv4。公网带宽建议至少 10Mbps；有 20Mbps 或更高峰值的合适套餐可以优先比较，同时查看限速规则与月流量。套餐实际可选配置及价格以购买页面为准。

系统使用 Node 24 和 SQLite 单实例运行。暂不需要购买 RDS、负载均衡或 Kubernetes。若选配 ECS，使用同等配置并确认已购买公网带宽；不要误选只有内网 IP 的实例。多人课程的实际承载量取决于同时在线人数、操作频率和带宽，不能只根据内存推定，先用真实班级规模试运行。

中国内地节点配域名使用，通常需先完成 ICP 备案，确认所买实例满足当前备案资格；备案主体应与实际运营主体相符。租服务器的个人账号不等于当然可以代表学校办理主体备案。购买前可向阿里云确认个人课程教学网站与当前学校冠名的备案材料要求。

## 二、域名、解析和防火墙

1. 购买并实名域名，或使用获授权的现有域名子域名。以 `hr.example.cn` 为示例，不能照搬示例域名。
2. 完成适用的备案手续。云解析 DNS 新增 A 记录：主机记录 `hr`，记录值填服务器公网 IPv4。先不要添加没有对应 IPv6 服务的 AAAA 记录。
3. 阿里云轻量服务器的“防火墙”放行 TCP 80、443。若使用 ECS，则在安全组放行这两个端口。SSH 22 建议只对自己的管理 IP 开放；也可按控制台远程连接方式配置。
4. 如果另启用了 Ubuntu UFW，同样放行 Web 服务，并先确保管理通道可用，避免把自己锁在服务器外。
5. 不向公网开放应用的 8787 端口。它只在容器内部供 HTTPS 代理访问。

## 三、上传代码和安装 Docker

1. 通过阿里云控制台远程连接，或 SSH 进入服务器。
2. 按 Docker 官方 Ubuntu 安装说明安装 Docker Engine 与 Compose 插件：
   <https://docs.docker.com/engine/install/ubuntu/>
3. 验证：

```bash
sudo docker version
sudo docker compose version
```

4. 使用 SFTP 工具上传整个 `hotel-hr-online` 项目到 `/opt/wushanyuan`，保留文件夹结构。上传代码时排除 `data/`、本地日志、`server.pid`、`node_modules/`、`.env` 和私人登录信息。旧数据库通过下面的备份迁移步骤单独传输，不复制正在运行的数据库三件套。
5. 中国内地节点可能无法直接拉取 Docker Hub 镜像；构建失败时根据阿里云容器镜像服务控制台提供的实际可用方案配置镜像获取，或导入预构建镜像。不要随意使用不可信第三方镜像站。

## 四、配置 .env

```bash
cd /opt/wushanyuan/deploy
cp .env.example .env
nano .env
```

填写真实域名、联系邮箱、自己设置的长随机教师初始密码和班级口令。保存后：

```bash
chmod 600 .env
sudo docker compose config --quiet
```

`config --quiet` 只检查配置，不把密码展开打印到屏幕。不要把 `.env` 发到群里或提交代码仓库。

## 五、选择首次新建或保留旧数据

### 从空课堂开始

```bash
cd /opt/wushanyuan/deploy
sudo docker compose up -d --build
```

首次启动创建教师账号，密码来自 `.env`。默认教学班口令同样来自 `.env`。

### 保留当前学生、班级、成绩与记录

先约定迁移时间，暂停本地各班修改与提交，让学生确认保存。在本地教师端下载“备份全班数据库”，通过 SFTP 上传为服务器上的 `/opt/wushanyuan-import/hotel.sqlite`。文件不能放进 `public/` 或公开下载目录。

云端必须是尚未初始化的课堂数据卷。不要先执行空课堂的启动步骤。在 `deploy` 目录执行：

```bash
sudo docker compose build app
sudo docker compose run --rm --no-deps --user 0 --entrypoint sh \
  -v /opt/wushanyuan-import:/import:ro app \
  -c 'test ! -e /app/data/hotel.sqlite && cp /import/hotel.sqlite /app/data/hotel.sqlite && chown 1000:1000 /app/data/hotel.sqlite'
```

**只有上一条命令成功后**才继续启动。它会在目标数据库已存在时停止，避免覆盖云端已有学生记录。若提示数据库已存在，先核查云端是否已有数据，不要直接删除卷。

```bash
sudo docker compose up -d
```

旧数据库中的教师密码、班级口令、学生密码继续有效，`.env` 不会覆盖它们。使用原教师密码登录后更换初始/演示密码，再分享学生入口。迁移完成后让学生统一改用公网地址，本地系统保持暂停，防止出现两套不同的课堂存档。旧网址下尚未上传的浏览器副本不能自动跨域迁移，必须先在旧网址完成保存。

## 六、检查与使用

```bash
sudo docker compose ps
sudo docker compose logs --tail=80 app web
curl -fsS https://你的真实域名/api/health
```

Caddy 在域名解析正确、80/443 可达后自动申请 HTTPS 证书。失败时查看 `web` 日志，核对域名、DNS、备案接入状态、端口占用及防火墙，不要通过关闭 HTTPS 或移除安全 Cookie 来掩盖问题。

最终网址：

- 学生：`https://你的真实域名/?role=student`
- 教师：`https://你的真实域名/?role=teacher`

关闭手机 Wi-Fi，使用移动数据验证：学生登录、新增测试员工、确认服务器保存、教师看到记录、刷新后记录仍在、班级开关可同步。重启云端服务后再确认存档恢复。先用测试账号，再组织正式课堂试运行。

## 七、维护

- 数据卷 `wushanyuan_hotel_data` 保留数据库；Caddy 数据卷保存证书。不要执行 `docker compose down -v`，该参数会删除持久数据。
- 每节课后从教师端下载数据库备份，另存到其他设备；长期运营应配置定时数据库一致性备份及异机存储，并验证恢复。云盘快照可以补充，不能代替经验证的数据库备份。
- 更新代码前先备份，再在 `deploy` 目录执行 `sudo docker compose up -d --build`。此操作会保留数据卷。
- 主机、域名按期续费；Caddy 自动续证仍依赖域名解析及端口可用。
