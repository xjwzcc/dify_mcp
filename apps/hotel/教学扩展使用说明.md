# 苏州旅游职业学院 · 吴山苑酒店人力资源实训

本次更新沿用原局域网网址、账号、学生酒店存档及四项情境成绩。教师端和学生端均显示学院与酒店名称，每个页面底部显示教学用途、模拟数据及敏感信息提示。

## 教师端新增栏目

1. **课堂总览**：保留班级排名、任务通知、操作日志、密码管理及全班数据库备份。
2. **任务完成进度**：按学生与情境展示完成步骤、是否提交评分，以及工单提交与评价数量。
3. **学生数据面板**：搜索姓名或学号，查看情境总分、录用与绩效记录、操作参与情况、工单评分，并向学生发送指导。
4. **任务工单设计**：内置招聘、排班、绩效、离职四份工单，可新建及编辑学习目标、模块、操作步骤、应交成果、评分依据、满分、发布对象、截止时间和提交门槛。支持草稿、发布、关闭；对象可为全班或已注册学号。
5. **提交与批阅**：查看学生文字成果与提交时的业务进度摘要，评分、反馈或退回修改。学生重交后保留原成果和反馈历史。
6. **师生互动**：教师向全班或指定学生发送指导，学生向教师提问。学生不能查看其他学生的个人提问或定向指导。

已收到提交的工单不能修改模块、满分、发布对象及完成门槛，避免评价口径中途改变；可另建新工单。截止时间按北京时间解释。工单教师评分与原有400分情境成绩分开统计，不自动相加。

## 学生业务扩展

### 招聘岗位设计

在招聘管理中点击职位“编辑”，保存岗位职责、任职能力、经验与测评分要求、薪酬范围、班次与休息说明，以及对应的面试问题，再发布职位。前厅、客房、餐饮、工程、安保有不同的岗位参考内容。招聘条件应围绕岗位能力，避免无关限制。

筛选时可查看模拟学习经历、工作经历、技能证据、服务案例、班次可用性及求职动机。学生需写出招聘要求与履历证据的对应关系，提出追问及评分标准。面试阶段另记录沟通、操作、风险意识三项评价与回答证据。

自定义招聘要求用于岗位分析和教师工单评价。原“旺季招聘”情境为保持历史可比，仍按技能至少75分、相关经验至少1年的基准判定。

### 排班任务

按部门、周设置入住率及早中夜班最低人数和标准计划工时，写明配置依据。可以批准请假、指定拟协调替岗人员、套用个人班次模板、记录夜班训练与实际加班。

校验包括请假冲突、班次人数不足、夜转早（含跨周）、连续七天、超过设定周工时、未完成夜班训练等。批准请假只将**当前所选周内**的相应日期设为休；其他周仍需逐周调整，系统会提醒冲突。替岗人登记不等于自动调班，需在表中落实，避免覆盖原有班次。入住率用于需求分析，不直接代表法定人员配额；计划超时不自动记为实际加班工资。

### 离职任务

郑涛（E0011）的工单新增申请类型、通知日期、最后工作日、依据说明、交接清单、结算明细与离职证明。

- 一般辞职情境核对30日书面通知，试用期情境核对3日；协商解除或主张法定即时解除另行记录依据。
- 交接未完可登记事项、责任人及后续计划，不以未交接为由当然阻断法定手续。
- 分列岗位工资、绩效、已核实平日延时加班、其他应付款与有依据扣项；该争议场景已确认20小时加班，不能少计。
- 记录证明及送达、社保档案等后续事项，不要求放弃合法工资，不设置简单的离职罚款。
- 未来离职日期可进行完整教学推演，页面会明确提示；模拟状态变化不代表真实用工手续已经生效。

离职结算工单不会重复增加月工资加班数；原争议处理模块负责登记已核实的月度加班。旧版已办结记录及成绩保留，可再补充详细工单。

## 推荐课堂顺序

教师设计并发布工单 → 学生按要求完成业务操作 → 学生在“课堂任务工单”提交至少30字的成果与反思 → 教师批阅并反馈 → 必要时退回重交 → 学生查看历史反馈并改进。

## 本次验证

服务端测试覆盖定向发布、草稿隐藏、学生权限、重复提交保护、评分范围、退回重交、旧批阅版本拒绝、修订历史、留言隔离及重启后恢复；并验证新增岗位、排班规则、离职申请字段持久化。

浏览器实际验证了学院酒店标识、教师导航、原成绩保留、绩效工单提交与92分反馈、岗位设计保存、职位发布、简历筛选保存、排班需求保存和离职日期核对。正式实例仅使用DEMO001演示账号进行业务验收，其他学生记录未改动。升级前数据库备份位于 `data/before-teaching-upgrade.sqlite`。
